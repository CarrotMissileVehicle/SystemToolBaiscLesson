## 一、实验目的

1. 学会把含糊的协作材料改写成可执行、可复现的信息。
2. 掌握 Issue 的要素：环境、复现命令、期望结果、实际结果，未知信息标注"待确认"。
3. 学会书写祈使语气的提交信息标题，以及带 Blocking／Suggestion／Nit 分级的具体评审意见。

## 二、实验环境

- 操作系统：Windows 11 本地编写，Ubuntu 25.04 远程验证
- 命令行工具：bash、vim
- 其他软件：greetlab 0.1.0（sdt-greet 命令行包）

## 三、实验步骤与代码

### 步骤1：阅读低质量协作材料与已知事实

给定内容：

```markdown
Issue：Windows上运行不了，尽快修复。
提交信息：fix bug
评审意见：这里写得不好，重写。
已知事实：运行 sdt-greet --name " " 时仍输出 Hello, !，并以0退出。
```

这三段材料缺少环境、复现步骤、期望行为与风险说明，接收者无法据此行动。

### 步骤2：重写 Issue、提交信息与评审意见

在 `~/lab/q11/communication.md` 中重写，未知信息标注"待确认"：

```markdown
# communication.md

## Issue

- 环境：Windows、Python 3.13、greetlab 0.1.0（版本待确认）
- 复现命令：`sdt-greet --name " "`（报错待确认）
- 期望结果：空白姓名非零退出码结束、不输出问候
- 实际结果：输出 `Hello, !`，退出码 0

## 提交信息

标题：Reject blank --name with exit code 2

正文：`main()` 未校验空白姓名。修复：`parse_args()` 后调用 `p.error()` 拒绝空白输入（退出码 2）。

## 评审意见

Blocking：`--name " "` 仍输出问候且以 0 退出，空数据会污染下游。请在 `main()` 中校验 `a.name.strip()` 为空时调用 `p.error()`（退出码 2）。
```

## 四、实验结果

### 4.1 结果展示

- Issue 包含环境、复现命令、期望结果、实际结果四要素，真实的"报错内容"与"具体版本"标为**待确认**，不再写"运行不了"这种无法复现的表述。
- 提交信息标题为祈使语气 `Reject blank --name with exit code 2`，正文说明问题（未校验空白姓名）与解决方案（`p.error()`，退出码 2）。
- 评审意见标注 **Blocking**，指明具体行为（仍输出问候、以 0 退出）、风险（空数据污染下游）和建议动作（校验 `a.name.strip()` 并调用 `p.error()`）。
- 全文 398 字，满足 400 字限制。

### 4.2 结果分析

- "可执行信息"的关键是把**事实**（命令、输出、退出码）与**意图**（期望行为、风险）分离，让协作对象无需追问即可复现并行动。
- 标注 Blocking 表明该缺陷阻塞合入；若只是格式问题，则用 Suggestion 或 Nit，帮助接收者区分优先级。

## 五、实验总结

通过本次实验，我掌握了以下技能：

1. 用"环境＋复现命令＋期望结果＋实际结果"的结构改写 Issue，并把未知信息显式标为"待确认"。
2. 书写祈使语气的提交信息标题并补充问题／方案正文。
3. 撰写带 Blocking／Suggestion／Nit 分级、包含行为／风险／建议的评审意见。
